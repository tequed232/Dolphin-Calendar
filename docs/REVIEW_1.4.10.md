# 1.4.10 全项目审查与修复记录

本轮以已发布的 1.4.9 提交 `f81ae8678616649283c7cc2ed4eaf176581733c7` 为基线，按用户 2026-10-13 的要求重新审查界面交互、数据处理及流畅性，并修复实际复现的问题。下列22项台账及完整本地验证均对应1.4.10；最终正式APK已完成原签名覆盖升级。线上版本与提交检查按[GitHub Release](https://github.com/tequed232/Dolphin-Calendar/releases/tag/v1.4.10)、[Actions](https://github.com/tequed232/Dolphin-Calendar/actions)和交付的发布收据核对，不用1.4.9的成绩替代。

这里的“后端逻辑”指浏览器和 Android 内部的数据解析、IndexedDB、保存队列、原生桥接与文件操作。项目仍没有自建业务服务器，也没有新增云同步服务。

## 流畅性测量与限制

性能对比使用同一隔离 Chromium、700 门虚构课程、24 节配置，两批各记录 9 次日期切换。计数检查用来防止重复计算回退；时间是该机器上的小样本观察值，不用作跨设备硬阈值。

| 指标 | 1.4.9 基线 | 修复后 | 可以支持的结论 |
| --- | ---: | ---: | --- |
| 一次日期切换中的 Date 构造 | 8,629–8,651 | 219–241 | 该样本重复对象构造减少约 97% |
| 181 项工作日窗口的日历推进 | 22,662 次 | 252 次 | 推进次数减少约 98.9%，窗口结果保持一致 |
| 同帧 60 次滚动的布局读取 | 840 次同步读取 | 0 次同步读取，下一帧 14 次 | 将事件突发中的重复同步读取合并为一次采样 |
| 同一单元格 30 次指针移动的冲突列排序 | 210 次 | 0 次 | 指针未改变目标单元格时不重复排版 |
| 点击至两帧后观察值 P50 | 84.8 ms | 83.5 ms | 本次样本中位数接近 |
| 同批观察值 P95 | 183.3 ms | 184.7 ms | 高分位耗时没有改善 |

这证明减少了无用计算、布局读取和封面处理，不能据此声称整体帧率或输入延迟大幅提升。DOM 渲染、设备性能、输入法、系统省电和课表规模仍影响实际体验；本次 P95 没有改善。原始基线与修后记录为发行验证目录中的 `performance-baseline.json`、`performance-improved.json`，本版集成性能记录由测试读取实际版本号生成。
